# Rokn Om Alqura — ركن أم القرى · Website + Store Management System

Two connected systems in one project:

1. **Customer website**: a bilingual (English / Arabic RTL) fabric e-commerce storefront.
2. **Staff system** at `#en.admin` (or `#ar.admin`): a protected area that customers never see. It is reached by direct URL or the small "Staff login" link in the footer.
   - It covers the dashboard, POS, sales and website orders, products, categories, collections and the media library.
   - Stock: inventory, fabric rolls, barcode labels, suppliers and purchase orders.
   - Money: expenses, the daily report, sales and inventory reports.
   - People and system: users, roles and permissions, activity logs, notifications, printers and settings.

Everything is plain HTML/CSS/JS (no build step). The API server is plain Node with no dependencies.

## How the pieces connect

```
storefront (index.html)  ── reads ──▶  public catalogue snapshot (prices, live stock, categories, settings)
        │ checkout                              ▲ published after every admin change
        ▼                                       │
  website orders  ──────────▶  services.js  (auth · RBAC · stock ledger · orders · POS · reports · audit)
                                    ▲                     ▲
                    browser demo store (IndexedDB)   server/ API + SQLite / PostgreSQL
```

`assets/js/biz/services.js` holds all business rules, and the same file runs in two places:

- **Production**: on the Node server (`server/server.js`). Permissions are enforced server-side, sessions use an HttpOnly cookie, and passwords are hashed with PBKDF2. See `server/README.md`.
- **Offline demo**: in the browser, when no API is configured (this preview). Data is kept in IndexedDB and passwords are still hashed with PBKDF2. Because it runs in the browser, permission checks can be bypassed by someone with dev-tools on their own copy. That is why a real launch uses the server.

## Demo data

The demo data is generated (deterministically) and labelled clearly:

- Sample sales over the last 75 days.
- Demo customers named "Demo Customer 01…" and suppliers named "Demo Supplier — …".
- Demo staff accounts, one per role, all with the password `Rokn@2026`.
- Demo expenses, rolls and purchase orders.

Every demo row has `demo: true`. Screens show a **DEMO** tag and a banner. *Settings → Backup & data → Remove demo data* deletes all of it and deactivates the demo staff accounts. Nothing in the demo data is the store's real trading history.

## Structure

```
index.html / artifact.html     shells (generated by tools/build_html.py)
assets/css/main.css            storefront styles        assets/css/admin.css  staff system styles (lazy-loaded)
assets/js/config.js            storefront defaults (overridden by Admin → Settings)
assets/js/data/*.js            catalogue (demo + in-store products), lookups, reviews, policies
assets/js/biz/schema.js        tables, permission modules, role matrix, settings defaults
assets/js/biz/services.js      business logic + permission-checked RPC methods
assets/js/biz/seed.js          base data + DEMO generator
assets/js/biz/db.js            in-memory table store with transactions
assets/js/biz/local.js         API client (server mode / offline demo mode)
assets/js/biz/pub.js           storefront ← admin bridge (prices, stock, settings, categories)
assets/js/admin/*.js           i18n, UI kit (tables, charts, exports, printing, barcodes), shell, pages
server/                        Node API server, SQLite store, schema.sql (PostgreSQL)
tools/qa_admin.py              admin page matrix (EN/AR × desktop/tablet/phone)
tools/qa_admin_flow.py         business flow test (sale → stock, refund, PO receive, permissions, web order…)
```

## Printing and exports

- **Receipts**: 58 mm and 80 mm, bilingual, with barcode and QR code.
- **Invoices and quotations**: A4.
- **Labels**: barcode labels (Code 128, 50×30 mm) for products and fabric rolls.
- **Reports**: A4.

All of these open as a print preview in the browser's print dialog, with page sizes taken from Admin → Printers. Use "Save as PDF" in that dialog to get a PDF. Tables also export to CSV and Excel.

Some viewers block printing and downloads, including the Claude artifact viewer. Open the site in a normal browser tab to print or download.

## Before launch

See `server/README.md` → *Before going live*. In short:

- Run the server and remove the demo data.
- Set up real staff accounts.
- Confirm prices and stock.
- Connect KNET / card payments.
- Serve the site over HTTPS.
